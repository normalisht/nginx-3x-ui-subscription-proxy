# CLAUDE.md

Прокси подписок 3x-UI: один Go-сервис (`subproxy`) собирает подписки нескольких серверов 3x-UI и сторонних VPN-сервисов в одну ссылку. Что умеет и как запускать — `README_RU.md` (и `README.md` на английском, держать их одинаковыми).

## Устройство

- `config.go` — настройки из переменных окружения (`loadConfig(getenv)`), проверка обязательных.
- `fetch.go` — скачивание источников (параллельно, порядок результатов сохраняется), декодирование base64, сборка подписки; JSON-режим: `deepMerge` и `dedupeRemarks`.
- `main.go` — HTTP: `/<SUB>/<id>`, `/routing/` (файлы из `ROUTING_DIR`), `/healthz`; режим TLS через `autocert`; подкоманда `healthcheck` для Docker.
- `compose.yaml` — самостоятельный режим (`TLS=1`, порты 80/443 → 8080/8443, том `certs`); `compose.edge.yaml` — за `../edge-proxy`, HTTP на `subproxy:8080` в сети `proxy`. Режим выбирает `COMPOSE_FILE` в `.env`.

## Правила

- Комментарии, сообщения логов и ошибок, имена тест-кейсов, коммиты — по-русски; идентификаторы — по-английски.
- Внутри контейнера — только непривилегированные порты: процесс в distroless работает не от root.
- В лог — только хост источника: в пути и параметрах ссылок — id подписок.
- `InsecureSkipVerify` у клиента источников — намеренно: у панелей 3x-UI бывают самоподписанные сертификаты.
- Новая переменная окружения — в `.env.example`, обе README и таблицу настроек.
- Меняются адрес или порт сервиса в режиме edge — поправить upstream `subproxy` в `../edge-proxy/nginx.conf.template`.

## Проверка

- `make check` — gofmt, `go vet`, тесты. Тесты табличные, источники — `httptest`-серверы (`newSource`).
- Образ: `docker build -t subproxy:test .` и запуск с `-e TLS=0 -e SERVERS=…`; `/healthz` и `/sub/<id>` на 8080.
- `.env` не читать и не выводить: в нём адреса подписок.
